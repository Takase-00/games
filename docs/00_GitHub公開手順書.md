# GitHub公開手順書（全アプリ共通）

この資料は、Claude上で完成したゲームを、GitHub Pagesを使って誰でも遊べるように一般公開するための手順です。

作業は「Claudeが行うこと（AI内）」と「管理者が行うこと（AI外）」に分かれています。各章の見出しに担当を書いています。

---

## 1. 全体像

### 1-1. 役割分担

| 担当 | 作業 |
|---|---|
| **Claude（AI内）** | 公開用ファイルの作成、公開用ファイルの動作確認、アップロードに必要な情報のまとめ、個別仕様書へ反映する内容のまとめ |
| **管理者（AI外）** | GitHubのアカウントとリポジトリの管理、ファイルのアップロード、GitHub Pagesの設定、公開後の動作確認、公開URLの管理と告知、更新・公開停止 |

- 公開作業は、管理者から依頼があって初めて始める（共通基盤と設計思想「1-2. 役割分担」のとおり）
- ClaudeはGitHubを直接操作しない。アップロード、設定変更、公開の判断はすべて管理者が行う
- GitHubのパスワードやアクセストークンは、チャットに貼らない。Claudeからも求めない

### 1-2. 公開までの流れ

| 順 | 担当 | 作業 | 章 |
|---|---|---|---|
| 0 | 管理者 | 初回だけ、GitHubの準備をする | 3章 |
| 1 | 管理者 | そのアプリのチャットで、Claudeに公開用ファイルの作成を頼む | 4章 |
| 2 | Claude | 公開用の `index.html` を作り、確認して渡す | 5章 |
| 3 | 管理者 | ファイルをGitHubにアップロードし、公開した版にタグを付ける | 6章 |
| 4 | 管理者 | 公開URLで動作を確認する | 6章 |
| 5 | 管理者 | 公開URLをそのアプリのチャットに伝える | 6章 |
| 6 | Claude | 個別仕様書に反映する内容（公開URL・変更履歴）をまとめる | 6章 |

## 2. 公開の構成（全アプリ共通のルール）

### 2-1. リポジトリとフォルダ

リポジトリは1つにまとめ、アプリごとにフォルダを分けます。GitHub Pagesの設定が1回で済み、管理も楽になります。

```
games/                ← リポジトリ（名前は例）
├─ .nojekyll          ← 中身は空。GitHubの余計な変換を止めるためのファイル
├─ README.md          ← 公開中のゲームとURLの一覧（管理用）
├─ 略称A/
│  ├─ index.html      ← ゲーム本体
│  └─ ogp.png         ← URLを貼ったときのサムネイル（任意）
└─ 略称B/
   └─ index.html
```

公開URLは次の形になります。

```
https://ユーザー名.github.io/games/略称/
```

### 2-2. 守るルール

- **フォルダ名はアプリの略称**にする。半角の小文字・数字・ハイフンだけを使い、保存キー（`略称-best` など）の略称と同じにする
- **ゲームのファイル名は必ず `index.html`**（小文字）。名前が違うと、URLを開いても表示されない
- 同じ `ユーザー名.github.io` で公開したゲームは、保存データ（`localStorage`）の置き場所を共有する。**保存キーは必ず「略称-項目」にして、ほかのゲームと重ならないようにする**
- 一度公開したフォルダ名は変えない。変えるとURLが変わり、シェアされたリンクが切れる

## 3. 【管理者】初回だけ行う準備

### 3-1. GitHubのアカウントを作る

https://github.com で無料のアカウントを作ります。ユーザー名は公開URLに入るので、人に見られても問題ない名前にします。

### 3-2. リポジトリを作る

1. 画面右上の「+」→「New repository」を選ぶ
2. 「Repository name」に `games` などの名前を入れる（URLの一部になる）
3. 公開範囲は「Public」を選ぶ
4. 「Add a README file」にチェックを入れる（`main` ブランチが最初から作られ、次の設定がしやすくなる）
5. 「Create repository」を押す

> 無料プランでは、GitHub PagesはPublic（公開）のリポジトリでしか使えません。リポジトリの中身は誰でも見られるので、パスワードや個人情報などは絶対に置かないでください。

### 3-3. `.nojekyll` ファイルを置く

1. リポジトリのトップで「Add file」→「Create new file」を選ぶ
2. ファイル名に `.nojekyll` と入力する（中身は空のまま）
3. 「Commit changes」を押す

### 3-4. GitHub Pagesを有効にする

1. リポジトリ上部の「Settings」を開く
2. 左側のメニューから「Pages」を開く
3. 「Build and deployment」の「Source」で「Deploy from a branch」を選ぶ
4. 「Branch」で `main` と `/(root)` を選び、「Save」を押す
5. 数分待ってからページを再読み込みすると、上部に「Your site is live at …」と表示される

これで準備は完了です。以後、`main` ブランチにファイルを追加・更新するたびに、自動で公開ページに反映されます。

## 4. 【管理者】Claudeに公開用ファイルを頼む

公開したいアプリのチャットで、次のように頼みます。

```
このアプリをGitHub Pagesで一般公開します。公開用ファイルを作ってください。
最新版：https://claude.ai/artifact/xxxxxxxx
公開先URL：https://ユーザー名.github.io/games/略称/
サムネイル画像：あり／なし
```

- 公開先URLを伝えると、Claudeがシェア文やOGP（URLを貼ったときの表示）に正確なURLを入れられる
- サムネイル画像は任意。「あり」にすると、XなどにURLを貼ったときに大きな画像付きで表示される

---

## 5. 【Claude】公開用ファイルを作る

### 5-1. 作るもの

| ファイル | 必須 | 内容 |
|---|---|---|
| `index.html` | 必須 | Claude上の最新版をもとにした公開用のゲーム本体 |
| `ogp.png` | 任意 | 1200×630pxのサムネイル画像。管理者から頼まれたときだけ作る |

### 5-2. Claude上の版から変えるところ

ゲームの遊び方や見た目は変えません。変えるのは、公開に必要な次の部分だけです。

| 項目 | 内容 |
|---|---|
| シェアの投稿文 | ページのURL（`location.href` から `#` 以降を除いたもの）と、ゲーム名のハッシュタグを付ける |
| タイトルと説明 | `<title>` と `<meta name="description">` を設定する |
| OGP | `og:type`、`og:title`、`og:description` を設定する。公開先URLが分かっていれば `og:url` も入れる。画像があるときは `og:image`（`https://` から始まる完全なURL）と `twitter:card`（`summary_large_image`）、ないときは `twitter:card`（`summary`）にする |
| ファビコン | ゲームに合う絵文字1つをSVGとして埋め込む |

### 5-3. 確認すること

共通基盤と設計思想「5. 品質確認の手順」を、公開用ファイルに対しても行います。加えて、次の点を確認します。

- 外部から読み込んでいるのがGoogle Fontsだけになっている
- Claude上でしか動かない機能（Claude専用の保存機能やAPIなど）を使っていない
- 保存キーが「略称-項目」の形になっている
- シェアボタンを押したとき、投稿文にURLとハッシュタグが入る
- ファイル名が `index.html` になっている

問題が見つかったら、その場で直してから渡します。

### 5-4. 管理者に渡すもの

ファイルと一緒に、次の「公開メモ」をチャットで伝えます。

```
フォルダ名：略称
公開する版：v2.0
アップロードするファイル：index.html（、ogp.png）
公開URL：https://ユーザー名.github.io/games/略称/
コミットメッセージ案：略称 v2.0: 公開
タグ：略称-v2.0
Claude上の版との違い：シェア文にURLとハッシュタグ、OGP、ファビコンを追加
```

### 5-5. Claudeがやらないこと

- GitHubへのアップロード、設定の変更、アカウントの操作
- 公開するかどうか、いつ公開するかの判断
- 管理者からの依頼がない状態での、公開用ファイルの作成

## 6. 【管理者】アップロードと公開

### 6-1. ブラウザからアップロードする（新しいアプリ）

1. PCで、アプリの略称と同じ名前のフォルダを作り、Claudeから受け取ったファイルを入れる
2. GitHubのリポジトリのトップで「Add file」→「Upload files」を選ぶ
3. **フォルダごと**ドラッグ＆ドロップする（フォルダ名も一緒に登録される）
4. 画面下のメッセージ欄にコミットメッセージ（例：`略称 v2.0: 公開`）を入れて、「Commit changes」を押す

### 6-2. Gitコマンドでアップロードする場合

```bash
git clone https://github.com/ユーザー名/games.git
cd games
mkdir 略称
# 受け取った index.html（と ogp.png）を「略称」フォルダにコピーしてから
git add 略称
git commit -m "略称 v2.0: 公開"
git push origin main
git tag 略称-v2.0
git push origin 略称-v2.0
```

### 6-3. 公開後の確認

数分待ってから、公開URLを開いて確認します。

- [ ] スマホのブラウザでタイトル画面が表示される
- [ ] Claudeにログインしていない状態（プライベートブラウズなど）でも最後まで遊べる
- [ ] 効果音が鳴る（鳴らない場合はマナーモードと、画面右上の音ボタンを確認）
- [ ] 「結果をシェア」の投稿文に、公開URLとハッシュタグが入っている
- [ ] もう一度遊ぶと、ベスト記録などの保存内容が残っている
- [ ] XなどにURLを貼ると、タイトルと説明が表示される（反映に時間がかかることがある）

### 6-4. 公開したことをClaudeに伝える

そのアプリのチャットで、公開URLを伝えます。

```
GitHubで公開しました。
公開URL：https://ユーザー名.github.io/games/略称/
```

Claudeは、個別仕様書に反映する内容（基本情報への公開URLの追加、変更履歴の1行）をまとめて返します。

### 6-5. 公開した版にタグを付ける

公開した版の印として、タグを付けます。あとから「公開していた版」に戻したり、見比べたりするときの目印になります。

- **ブラウザの場合**：リポジトリのトップ右側の「Releases」→「Create a new release」を開き、「Choose a tag」に `略称-v2.0` と入力して作成する。タイトルにも同じ名前を入れ、「Publish release」を押す
- **Gitコマンドの場合**：6-2の最後の2行（`git tag` と `git push origin 略称-v2.0`）

### 6-6. 公開一覧を更新する

リポジトリの `README.md` に、公開中のゲームとURLを追記しておきます。

```markdown
| ゲーム | URL | 公開日 |
|---|---|---|
| ゲーム名 | https://ユーザー名.github.io/games/略称/ | 2026-10-19 |
```

## 7. 更新するとき

| 担当 | 作業 |
|---|---|
| Claude | Claude上の版を改修したとき、変更点のまとめに「公開版への反映が必要」と書き添える。管理者から頼まれたら、最新版をもとに公開用の `index.html` を作り直し、5章と同じ確認をして渡す |
| 管理者 | GitHubで該当のフォルダを開き、「Add file」→「Upload files」で新しい `index.html` を上書きし、`略称 v2.1: 変更内容` の形のコミットメッセージで「Commit changes」を押す。そのあと6-5のとおりタグを付ける |

- 公開後の改修をClaude Codeで行う場合は、「00_開発の進め方.md」の手順に従う
- 公開URLは変わらないので、すでにシェアされたリンクもそのまま最新版になる
- 反映には数分かかる。古いままなら、ページの再読み込みかプライベートブラウズで確認する

---

## 8. 【管理者】公開を止めるとき

| 範囲 | 方法 |
|---|---|
| 1つのゲームだけ止める | そのフォルダ内のファイルを削除してコミットする。README.mdの一覧からも外す |
| サイト全体を止める | 「Settings」→「Pages」で、「Branch」の選択を「None」に戻して保存する |

---

## 9. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| 「404」と表示される | 反映まで数分かかる。少し待って再読み込みする。フォルダ名とURLの略称が一致しているか、ファイル名が小文字の `index.html` か確認する |
| 画面が真っ白になる | フォルダの中にさらにフォルダができていないか（`略称/略称/index.html` になっていないか）確認する |
| 更新したのに古いまま | 数分待ってから再読み込みする。プライベートブラウズで開くと確実 |
| URLを貼ってもタイトルが出ない | OGPの設定を確認する。XなどのSNS側で反映に時間がかかることがある |
| ほかのゲームと保存データが混ざる | 保存キーの略称がほかのゲームと重なっていないか確認する（2-2） |
| 文字の形がいつもと違う | Google Fontsを読み込めていない。通信状況によるもので、遊ぶのには影響しない |

---

## 10. セキュリティの注意

- Publicのリポジトリは、誰でも中身を見られる。パスワード、APIキー、個人情報は置かない
- GitHubのパスワードやアクセストークンは、Claudeを含め、どのチャットにも貼らない
- 公開URLは個別仕様書とREADME.mdに記録し、どのゲームがどこで公開されているかを管理者が把握できるようにする
