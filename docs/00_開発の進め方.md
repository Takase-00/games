# 開発の進め方（claude.ai と Claude Code の使い分け）

この資料は、ゲームを「企画・試作」から「一般公開後の改修」まで進めるときの、作業場所とバージョン管理の進め方をまとめたものです。

作業は「Claudeが行うこと（AI内）」と「管理者が行うこと（AI外）」に分けて書いています。

---

## 1. 全体像

### 1-1. 段階ごとの作業場所

| 段階 | 作業場所 | 主な作業 | 最新版の置き場所 |
|---|---|---|---|
| ① 企画・試作 | claude.aiのプロジェクト（アプリごとのチャット） | 企画、実装、Claude上で遊びながら調整 | Claude上のArtifact |
| ② 初回の一般公開 | claude.ai → GitHub | Claudeが公開用ファイルを作り、管理者がGitHubに置く（「00_GitHub公開手順書.md」） | GitHubのリポジトリ |
| ③ 公開後の改修 | Claude Code（手元の `games` リポジトリ） | 改修、確認、版番号の更新、コミット | GitHubのリポジトリ |

- **一度GitHubで公開したアプリは、リポジトリのファイルを最新版として扱う**。以後の改修はClaude Codeで行い、Claude上のArtifactは試作の記録として残す（更新しない）
- 公開済みのアプリで大きな作り直しをclaude.aiで試したいときは、リポジトリの `index.html` をチャットに添付して始める。できあがったファイルは、Claude Codeでリポジトリに取り込む

### 1-2. なぜ使い分けるのか

| | claude.ai | Claude Code |
|---|---|---|
| 得意なこと | 企画の相談、試作、作ってすぐスマホで遊べる | リポジトリのファイルを直接編集し、差分の確認・コミット・ブランチ・巻き戻しまでできる |
| 準備 | 不要 | PCにClaude CodeとGitが必要 |
| バージョン管理 | Artifactは同じリンクが上書きされるだけ。版は仕様書の変更履歴で管理する | Gitの履歴とタグで、すべての版が残る |

---

## 2. 役割分担

| 段階 | Claude（AI内） | 管理者（AI外） |
|---|---|---|
| ① 企画・試作 | 企画の具体化、実装、確認、不具合の修正、Artifactでの公開、仕様書の作成 | 企画の判断、Claude上での試遊、仕様書をチャットに渡す |
| ② 初回の一般公開 | 公開用ファイルの作成と確認、公開メモ | GitHubへのアップロード、タグ、動作確認、URLの管理 |
| ③ 公開後の改修 | 実装、確認、不具合の修正、版番号と仕様書の更新、`main` へのコミット（承認後）、push、タグの公開 | 依頼、コミットの承認、公開ページでの動作確認 |

- Claude Codeは作業用ブランチを作らず `main` で作業し、push まで行う。リポジトリに置く `.claude/settings.json` で、コミットとマージとタグ付けは毎回管理者の承認が必要な設定にし、強制pushと履歴の書き換えは禁止している
- `main` ブランチにpushすると、すぐに一般公開される。確認で問題が残っているときは、Claude Codeは push せずに報告する

---

## 3. バージョン管理のルール

詳しくは「00_共通基盤と設計思想.md」の「7. バージョン管理」を参照してください。要点は次のとおりです。

| 項目 | ルール |
|---|---|
| 版番号 | `v＋メジャー.マイナー`（例：v2.1）。新しいアプリは v1.0 から |
| メジャーを上げる | ルールや仕組み、画面構成が変わる、大きな機能を追加する |
| マイナーを上げる | 数値の調整、演出の変更、不具合の修正 |
| 上げるタイミング | 1回の作業につき1つだけ上げる |
| ゲームの中 | `const VERSION = 'v2.1';` を定義し、タイトル画面に小さく表示する |
| コミットメッセージ | `略称 v2.1: 変更内容の要約` |
| タグ（一般公開した版） | `略称-v2.1` |

## 4. 【管理者】Claude Codeの準備（初回だけ）

### 4-1. Claude Codeをインストールする

公式ドキュメント（https://code.claude.com/docs/en/setup ）の手順でインストールします。執筆時点の公式の推奨は、次のコマンドです。

| 環境 | コマンド |
|---|---|
| macOS・Linux・WSL | `curl -fsSL https://claude.ai/install.sh \| bash` |
| Windows（PowerShell） | `irm https://claude.ai/install.ps1 \| iex` |

- Windowsでは、Git for Windowsも入れておくことが推奨されている
- 初回の起動時に、Claudeのアカウントでログインする
- インストール方法は変わることがあるので、うまくいかないときは公式ドキュメントを確認する

### 4-2. リポジトリを手元に用意する

```bash
git clone https://github.com/Takase-00/games.git
cd games
```

### 4-3. Claude Code用のファイルを置く

次のファイルをリポジトリに追加して、コミットとpushをします。

| 置き場所 | ファイル | 内容 |
|---|---|---|
| `games/CLAUDE.md` | CLAUDE.md | Claude Codeが毎回読み込む、このリポジトリの作業ルール |
| `games/.claude/settings.json` | settings.json | Claude Codeの権限設定（強制pushの禁止、コミットなどは承認制） |
| `games/docs/` | 00_共通基盤と設計思想.md など | 全アプリ共通の資料 |
| `games/specs/` | `略称.md` | アプリごとの個別仕様書（例：`specs/muki.md`） |

```bash
git add CLAUDE.md .claude docs specs
git commit -m "Claude Code用の設定と資料を追加"
git push origin main
```

- `.claude` フォルダは、名前が `.` で始まるため、MacのFinderやWindowsのエクスプローラーでは表示されないことがある
- リポジトリは公開設定なので、`docs/` と `specs/` も誰でも見られる。パスワードや個人情報は書かない

### 4-4. Claude Codeを起動する

```bash
cd games
claude
```

## 5. 公開済みのアプリをClaude Codeに移す（アプリごとに1回）

1. リポジトリに `略称/index.html` があることを確認する（一般公開したファイルがそのまま最新版になる）
2. claude.aiで使っていた個別仕様書を `specs/略称.md` という名前でリポジトリに置く
3. 仕様書の「現在の版」を、公開した版（例：v2.0）にしておく
4. 公開した版にタグ（例：`muki-v2.0`）が付いているか確認する。なければ付ける
5. 最初の改修のときに、Claude Codeがゲーム内の版番号表示を追加する

## 6. 公開後の改修の流れ（Claude Code）

| 順 | 担当 | 作業 |
|---|---|---|
| 1 | 管理者 | `git switch main` と `git pull` で最新にしてから `claude` を起動し、改修を依頼する |
| 2 | Claude Code | `CLAUDE.md`、共通資料、`specs/略称.md` を読む（作業用ブランチは作らず `main` で作業する） |
| 3 | Claude Code | 実装し、版番号と仕様書を更新し、確認する。見つかった不具合はその場で直す |
| 4 | Claude Code | `main` にコミットする（承認の確認が出るので、管理者が内容を見て許可する） |
| 5 | Claude Code | push してタグを付け、タグもpushする |
| 6 | Claude Code | 変更内容、新しい版番号、公開ページのURLを報告する |
| 7 | 管理者 | 公開ページをスマホで遊んで確認する。直したい点があれば、Claude Codeに修正を頼む |

### 依頼の例

```
muki を改修してください。
やりたいこと：後ろ姿に切り替えるボタンを追加したい
```

不具合の修正なら、症状をそのまま書きます。

```
muki の不具合を直してください。
症状：休養日を押したあと、体脂肪の表示が更新されない
```

### 手元での確認

リポジトリのトップで次を実行し、ブラウザで `http://localhost:8000/略称/` を開きます。

```bash
python3 -m http.server 8000
```

PCと同じWi-Fiにつながったスマホからは、`http://PCのIPアドレス:8000/略称/` で開けます。公開前にスマホの実機で確かめたいときは、コミットの承認の前にこの方法で遊んでみます。

### 公開まで（Claude Codeが実行するコマンド）

```bash
git push origin main
git tag muki-v2.1
git push origin muki-v2.1
```

公開後に直したい点が見つかったら、Claude Codeに修正を頼みます。修正は新しい版（例：v2.2）として公開します。

## 7. 過去の版を見る・戻す

| やりたいこと | 方法 |
|---|---|
| 過去の版の中身を見る | GitHubの「Releases」またはタグの一覧から、その版を開く。手元なら `git show muki-v2.0:muki/index.html` |
| 2つの版の違いを見る | `git diff muki-v2.0 muki-v2.1 -- muki/` |
| 公開中の版を前の版に戻す | Claude Codeに「muki を v2.0 の状態に戻して」と頼む。戻した内容を新しい版（例：v2.2）としてコミット・pushしてもらう |

- 履歴を消して戻す方法（`git reset --hard` や強制push）は使わない。「前の版に戻した」という記録も履歴に残す

---

## 8. 新しいアプリを作るとき

基本は ①→②→③ の順に進めます。

1. claude.aiのプロジェクトで新しいチャットを作り、企画・試作をする（v1.0）
2. 完成したら「00_GitHub公開手順書.md」の手順で一般公開する
3. 以後の改修はClaude Codeで行う

最初からClaude Codeで作ることもできます。その場合は、手元のブラウザやスマホで確認しながら進め、公開するかどうかは管理者が判断します。

---

## 9. 注意すること

- GitHubのパスワードやアクセストークンは、claude.aiのチャットにもClaude Codeにも貼らない
- Claude Codeの権限設定（`.claude/settings.json`）を変えるときは、強制pushと履歴の書き換えの禁止を外さない
- `main` へのpushは、確認が済んだ版だけにする
